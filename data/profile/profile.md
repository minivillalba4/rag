### EMASESA Metropolitana — Consultor DevOps / Desarrollo de aplicación técnica

En EMASESA Metropolitana, Ismael trabajó en el desarrollo de **LicitaIA**, una aplicación web interactiva orientada a estimar el presupuesto de actuaciones de renovación de redes de abastecimiento y saneamiento, sustituyendo cálculos manuales en hojas Excel por un proceso estandarizado, trazable y configurable.

Stack técnica real del proyecto:

- **Streamlit** como framework de UI multipágina (`calculadora`, `historial`, `admin_precios`).
- **clipspy / CLIPS** como motor de sistema experto basado en reglas. CLIPS dispara *warnings* y alertas técnicas cuando los inputs del presupuesto presentan inconsistencias o valores fuera de rango.
- **SQLite** como capa de persistencia con migraciones, para histórico de presupuestos y catálogo editable de precios.
- **Pandas** para el editor interno de catálogo de precios.
- **Docker** para empaquetado, portabilidad y despliegue reproducible (imagen `python:3.11-slim`, healthcheck, usuario no-root).
- **Pytest** con una suite extensa de tests automatizados.
- Arquitectura por capas: separación clara entre `domain`, `aplicacion`, `infraestructura`, `presupuesto`, `reglas` y `ui`.

Lógica de cálculo implementada conforme a la fórmula presupuestaria oficial (LCSP): costes directos por capítulo, recargo de Seguridad y Salud, Gestión Ambiental, Gastos Generales (13%), Beneficio Industrial (6%) e IVA (21%).

Este proyecto es relevante porque combina desarrollo de software, **inteligencia artificial simbólica real (motor de reglas CLIPS)**, persistencia de datos, despliegue reproducible y arquitectura limpia.

Elementos técnicos relevantes:

### Hotel Bookings — Predicción de cancelaciones de reservas (proyecto personal)

Proyecto personal de portfolio orientado a demostrar habilidades de Machine Learning end-to-end aplicado al sector hotelero.

Elementos del proyecto:

- Modelo de clasificación binaria con **LightGBM** para predecir si una reserva se cancelará.
- Pipeline de preparación de datos, ingeniería de features y validación de modelos.
- Aplicación interactiva con **Streamlit** para explorar datos y predicciones.
- Pestaña de **interpretabilidad con SHAP** que explica las predicciones del modelo a nivel global y por reserva individual.
- Empaquetado en entorno conda reproducible.

Es un proyecto orientado a mostrar capacidad para llevar un problema de ML desde el dato bruto hasta una herramienta interactiva con interpretabilidad de modelo, no un mero notebook.

### Portfolio RAG — Asistente conversacional sobre el propio perfil

Sistema RAG (Retrieval-Augmented Generation) que permite a un reclutador hacer preguntas sobre el perfil profesional de Ismael y recibir respuestas trazables, fundamentadas en este propio documento.

Stack técnica real:

- **Python** con organización modular (chunking, embeddings, vector_store, retriever, generation, pipeline, ui).
- **LangChain** para orquestación de la cadena RAG.
- **FAISS** como vector store local (persistencia en disco con `save_local` / `load_local`).
- **Hugging Face embeddings**: modelo `sentence-transformers/all-MiniLM-L6-v2`.
- **Hugging Face Inference API** para generación, con el modelo `Qwen/Qwen2.5-7B-Instruct`.
- **Gradio** como interfaz web (no FastAPI). El despliegue es local con manejo automático de puerto.
- Configuración centralizada (chunk size 500, overlap 100, retrieval top-k 3, temperatura 0.2).
- Trazabilidad: cada respuesta muestra las fuentes recuperadas del perfil.
- Suite de tests con pytest.

Este proyecto está orientado a demostrar conocimientos de IA aplicada, recuperación de información, embeddings, vector stores y construcción de asistentes basados en LLMs open source.
